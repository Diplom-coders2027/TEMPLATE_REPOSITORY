# Требования к оформлению пояснительной записки ВКР

В данной папке ведутся исходные материалы пояснительной записки (ПЗ), диаграммы, иллюстрации и презентации к докладу.

---

## 📐 1. Основные стандарты оформления (по ГОСТ 7.32 / ГОСТ 2.105)

При оформлении текста выпускной квалификационной работы необходимо строго соблюдать следующие типовые параметры (уточняйте методические указания конкретно вашей кафедры):

| Параметр | Требование |
| :--- | :--- |
| **Гарнитура (шрифт)** | Times New Roman (или PT Astra Serif / Liberation Serif) |
| **Кегль (размер шрифта)** | 14 пт (в таблицах, сносках допускается 10–12 пт) |
| **Межстрочный интервал** | Полуторный (1.5) |
| **Цвет шрифта** | Черный |
| **Поля страницы** | Левое: **30 мм**, Правое: **10–15 мм**, Верхнее: **20 мм**, Нижнее: **20 мм** |
| **Абзацный отступ (красная строка)** | **1.25 см** (одинаковый по всему тексту) |
| **Выравнивание текста** | По ширине страницы (с включенной автоматической расстановкой переносов) |
| **Нумерация страниц** | Сквозная, арабскими цифрами, по центру внизу страницы (без точки). На титульном листе и бланке задания номер **не ставится**, но включается в общую нумерацию. |

## 📑 2. Структура пояснительной записки

1. **Титульный лист** (по утвержденной форме кафедры)
2. **Задание на выполнение ВКР** (подписанное научным руководителем)
3. **Календарный план-график**
4. **Аннотация / Реферат** (на русском и английском языках, включая объем страниц, количество рисунков, таблиц, источников и ключевые слова)
5. **Содержание** (автоматически собираемое оглавление)
6. **Перечень сокращений и условных обозначений** (при наличии более 5 специфических терминов/аббревиатур)
7. **Введение**
   - Актуальность темы исследования
   - Объект и предмет исследования
   - Цель и задачи работы
   - Научная новизна и практическая значимость
   - Краткое описание структуры работы
8. **Раздел 1. Аналитическая часть**
   - Анализ предметной области и бизнес-процессов
   - Сравнительный обзор существующих аналогов и решений (сводная таблица)
   - Постановка задачи и формулирование требований (функциональные, нефункциональные)
9. **Раздел 2. Проектная / Архитектурная часть**
   - Архитектура системы (C4 / UML компонентная диаграмма)
   - Модель данных и проектирование БД (ER-диаграмма, описание сущностей и индексов)
   - Проектирование API и взаимодействия сервисов (Sequence диаграммы)
   - Проектирование интерфейса пользователя (Wireframes / макеты)
10. **Раздел 3. Технологическая реализация**
    - Обоснование выбора стека технологий, фреймворков и библиотек
    - Описание реализации ключевых алгоритмов и модулей
    - Обеспечение безопасности и авторизации
    - Инфраструктура развертывания (Docker, CI/CD)
11. **Раздел 4. Тестирование и оценка результатов**
    - Методика и план тестирования (Unit, Integration, E2E)
    - Результаты тестирования и покрытие кода
    - Нагрузочное тестирование / профилирование производительности (при необходимости)
    - Оценка достижения поставленных в ТЗ целей
12. **Раздел 5. Экономическая часть / БЖД** *(при наличии в учебном плане)*
13. **Заключение** (краткие выводы по каждому пункту задач из введения)
14. **Список использованных источников** (оформление строго по ГОСТ Р 7.0.100-2018 / ГОСТ 7.0.5-2008, от 25–40 актуальных источников)
15. **Приложения** (листинги критического кода, громоздкие схемы, акты о внедрении)

## 🖼 3. Правила оформления элементов текста

### Рисунки (схемы, диаграммы, графики)
- Все иллюстрации должны быть четкими, читаемыми и выполнены в векторном формате (SVG, PDF) или растровом высоком разрешении (PNG >= 300 dpi).
- На **каждый** рисунок в тексте **обязательно** должна быть прямая ссылка: `...как показано на рисунке 2.1...`. Рисунок помещается сразу после первого упоминания в тексте или на следующей странице.
- Подрисуночная подпись располагается **по центру под рисунком**:
  > *Рисунок 2.1 — Архитектурная схема взаимодействия микросервисов*

### Таблицы
- На каждую таблицу должна быть ссылка в тексте: `...приведены в таблице 1.2.`.
- Заголовок таблицы пишется слева над таблицей:
  > *Таблица 1.2 — Сравнительный анализ существующих решений*

### Листинги программного кода
- Короткие фрагменты кода (до 15–20 строк) допускается размещать в основном тексте с использованием моноширинного шрифта (Courier New / Consolas, 10–11 пт) и подписью:
  > *Листинг 3.1 — Реализация алгоритма вычисления ранга*
- Полные исходные тексты выносятся в **Приложения**.

## 🛠 4. Рекомендуемые форматы хранения в `docs/`

Вы можете выбрать удобный инструмент для написания записки:

1. **LaTeX / Typst (Рекомендуется):**
   - Позволяет версионировать текст в Git, видеть diff в PR, автоматически формировать ссылки и библиографию по ГОСТ (например, с пакетом `biblatex-gost`).
2. **Markdown + Pandoc:**
   - Быстрое написание глав с возможностью экспорта в DOCX / PDF.
3. **Microsoft Word / LibreOffice Writer (`.docx`):**
   - Допускается, однако помните, что бинарный diff в Git менее удобен для построчного ревью. Исходный DOCX рекомендуется сохранять в папке `docs/`.
   - Временные файлы Word (`~$*`) автоматически игнорируются через `.gitignore`.

### Хранение диаграмм
- Исходники диаграмм храните в редактируемом виде рядом с изображениями:
  - `docs/diagrams/*.puml` (PlantUML)
  - `docs/diagrams/*.drawio` (draw.io / diagrams.net)
  - `docs/diagrams/*.mmd` (Mermaid)
